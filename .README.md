# Edurod

Edurod is an internal web app for managing bus driver **occurrences** (incidents such as complaints, infractions or accidents) and computing each driver's **performance bonus** ("premiação") from them. The user interface is in Portuguese (pt-BR).

- **Occurrences**: register, edit, close and validate occurrences linked to a driver, vehicle, line and source.
- **Reports**: per-driver points and bonus for a date range, with PDF and XLSX export.
- **Admin**: manage users and roles, drivers, lines, vehicles, occurrence categories, types and sources, system variables (points per driver, maximum bonus), and the action log.

## Stack

| Layer    | Technology                                                            | Folder       |
| -------- | --------------------------------------------------------------------- | ------------ |
| Frontend | React 19, TypeScript, Vite, Chakra UI, AG Grid, served by nginx (HTTPS) | `frontend/` |
| Backend  | Node.js, Express, Mongoose, JWT auth                                  | `backend/`   |
| Database | MongoDB 8                                                             | `database/`  |

The three services run together through `docker-compose.yml`.

## Quick start (Docker)

Prerequisites: Docker with the Compose plugin.

```bash
cp .env.example .env         # then edit credentials, JWT_SECRET and VITE_BASE_URL
# put an SSL certificate in ssl/cert.pem and ssl/key.pem (nginx won't start without them)
docker compose up -d --build # or ./start.sh
```

| Service  | URL                                              |
| -------- | ------------------------------------------------ |
| Frontend | `http://<host>` and `https://<host>` (ports set by `FRONTEND_PORT` and `FRONTEND_HTTPS_PORT`, default 80/443) |
| Backend  | `http://<host>:8000` (responds `Backend is running!`) |
| MongoDB  | `<host>:27017`                                   |

Then register the first account at `/register` and give it the `admin` role directly in MongoDB. The [setup guide](docs/setup-guide.md) walks through this step.

## Roles

| Role     | Can                                          |
| -------- | -------------------------------------------- |
| `admin`  | Everything, including the Admin page         |
| `opener` | Create and edit occurrences                  |
| `closer` | Close/resolve occurrences                    |
| `viewer` | Read-only access                             |

Newly registered users have no roles until an admin assigns them.

## More documentation

- [docs/setup-guide.md](docs/setup-guide.md): full setup from scratch, local development, and migrating data from one server to another.
- `tools/db/migrate-server.sh`: run on a new server to copy the data from the old server's MongoDB. It never writes to the old server and refuses to overwrite existing data.
- `tools/db/copy-prod-to-dev.sh`: copies one MongoDB database to another with `mongodump`/`mongorestore`.
- `tools/scripts/docker-cleanup.sh`: interactive tool that frees Docker disk space.
